# Paragraph illustrations

## Reader behavior

Every image is attached to a stable paragraph ID and displayed after that paragraph in Reading view. The original EPUB/FB2 and spoken text remain unchanged. The newest version is shown inline; old versions remain in the paragraph's illustration panel. Removing the newest version can reveal a previous one. Images are shared across narration versions, so changing the voice or playback speed does not regenerate artwork.

Illustrated view shows the exact current paragraph's image or an explicit missing-image state. It does not reuse an earlier paragraph's image as though it belonged to the current passage. **Show this paragraph in text** opens the owning chapter and focuses its actual source anchor. Explicit navigation does not pause audio or immediately follow it away again. Original book figures stay available.

## Prepare images

Open **Book tools → Paragraph illustrations**, or a paragraph's illustration action. Choose this paragraph, every paragraph in the chapter, or primary-book paragraphs. Each is a separate request; chapter/book scope does not group scenes. Select a style and review the count. Enable optional online illustrations in Settings and explicitly consent before starting. The app does not request images merely because an ebook opens or playback reaches unillustrated text.

A run supports at most 5,000 paragraphs; larger selections are refused. A paragraph over 16,000 characters is never shortened or sent: the run skips it and lists it under `excluded` with its reason. A selection that contains only such paragraphs is refused, and the error names the paragraph and its chapter. Prepare larger books by chapter. Valid saved image files are reused. Missing files remain eligible. Creating a different result for one paragraph requires **Create a new version**; existing versions are retained. Bulk forced replacement is intentionally unavailable to avoid silently purchasing an entire second book.

The queue is durable, serial and separate from audio preparation. Stop keeps completed images. Reopen/resume processes unfinished items only. Failed or interrupted requests need explicit retry approval because the provider may have completed or charged work before the local failure. There is no automatic retry. A newly attached manual image takes precedence over a late result. Existing saved audio remains playable during an image request.

A saved run has its own approval checkbox, labelled with its style and unfinished paragraph count. The runtime computes that count (`resume` in run history and status) with the same saved-file checks that resume uses, so a paragraph whose saved image file is missing or corrupt counts as unfinished. Consent for a newly selected paragraph/chapter/book is not reused for an older run. The source paragraph and chapter displayed in a dialog remain fixed while playback moves.

When every paragraph already has a recorded result but final run status was interrupted, **Finish saved run** completes that bookkeeping locally. It needs neither online permission nor Codex and does not regenerate images. This does not restore intentionally deleted images; a later explicit preparation checks saved files as usual. Read-only source navigation now restores its paragraph on reopening, while browsing during audio playback keeps the listening position independent.

## Codex requirements and evidence boundary

Use an existing compatible Codex CLI installation, already signed in with access to built-in image generation. The app looks for `codex` on PATH first. On macOS and Linux it then checks `/opt/homebrew/bin`, `/usr/local/bin`, `~/.local/bin`, `~/.npm-global/bin`, `~/.volta/bin`, `~/.bun/bin` and the newest `~/.nvm/versions/node/*/bin` that contains it, plus the `%APPDATA%` and `%LOCALAPPDATA%` folders listed below when those variables are set. On Windows it checks only `.local\bin`, `.npm-global\bin`, `.volta\bin` and `.bun\bin` in the user profile, `%APPDATA%\npm`, `%LOCALAPPDATA%\pnpm` and `%LOCALAPPDATA%\Volta\bin`, and skips any folder without a drive or UNC prefix. On Windows the PATH lookup itself checks each PATH entry by its full folder path and never searches the current working folder; relative and drive-relative PATH entries are skipped. It does not start a login shell. Those folders are appended to the CLI's PATH so that an npm launcher can find `node`. The app invokes non-interactive Codex in a private temporary workspace with a paragraph brief and expected output schema. It requests `$imagegen`, validates the returned source ID and bitmap and saves it through the same decoder/storage path as manually attached images. This is optional online processing, not a bundled local image model. It consumes the user's Codex allowance; no free/unlimited-generation promise is made.

No actual Codex executable or account was available during the implementation checks. Those checks used controlled local processes/images. Native CLI discovery, sign-in, image-tool availability and returned file behavior must be verified on the target installation. An unsupported version, missing tool or failed generation reports an error. There is no automatic installation, Images API fallback or code-drawn substitute. The separate existing Images API disclosure is independently opt-in and independently billed. Its HTTPS connection trusts the certifi CA bundle in addition to the system default store when certifi is available; a certificate failure is reported as a secure-connection failure, not as a provider error.

Only selected paragraph text and its chapter/book metadata are supplied by the app, not the whole book or voice corpus. The external CLI has its own filesystem/authentication state; workspace-write does not prove complete read isolation. Stop cannot retract text already sent or guarantee no provider usage. This version has no shared visual character-reference bank, style-continuity guarantee or validated scientific-diagram pipeline.

## Storage and speed

Original accepted images stay in the local library; their display previews are bounded to 1280 pixels. Attached, generated and preview images are decoded only as PNG, JPEG, GIF, WebP or BMP; other formats are refused before decoding. Near-viewport loading, idle Blob-cache eviction and object-URL cleanup avoid eagerly decoding every paragraph image. Full book text remains in memory; one chapter's text is mounted. There is no new virtualization engine. These changes remove repeated work, not a measured promise about frame rate or hardware limits.

Image and generation revision polling returns small unchanged responses. Updated images are mapped by paragraph ID. No audio regeneration or export is needed when an image changes. Audio/subtitle exports remain the existing five formats; modified-EPUB/video export is not added.

Library schema 2 added image-run state and revision counters; the current library schema is 4, reached through transactionally checked upgrades. Existing book/generation/audio data are preserved. Use the matching frontend/core; older source releases refuse newer libraries.

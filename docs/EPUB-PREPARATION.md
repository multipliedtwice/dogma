# EPUB and FB2 preparation


Importing an EPUB now prepares its navigation, logical sections, source passages, local links and default narration selection before any inference is required. The local reader can open the resulting chapters without a model pack.

The reader toolbar has a **Book preparation** sheet. It shows title/author/language/format, the section list, default narration inclusion, character and pre-analysis segment counts, and import warnings. Sections can be opened directly from the sheet. The generation dialog offers the default primary text, current section, all sections including optional content, or an explicit selection. An empty selection is rejected instead of silently requesting the whole book.

The React/Radix/Vite production build and source-selection checks pass with the declared frontend dependency lock. Native Tauri and target-platform visual acceptance remain separate release checks.

### Model-free command line

After installing the declared core development dependencies:

```sh
python scripts/prepare_book.py /path/to/book.epub
python scripts/prepare_book.py /path/to/book.epub --output /path/to/new-prepared-directory
```

The first command prints the preparation report and cleans its temporary extraction. The second also saves:

- `book.json`: canonical book, navigation, source locations, sanitized rich passages and report.
- `preparation.json`: per-section metrics, defaults and warnings, with book identity.
- `speech-inputs.jsonl`: ordered, bounded pre-analysis text inputs for default narration; each carries chapter/passage IDs, exact prepared-text offsets and a structural scene ID.
- `books/<book-id>/source.epub` and `assets/`: byte-identical original plus converted local figures.

An existing output path, including a symbolic link, is refused without overwriting it. A caught publication failure removes the new destination. Publication is not a guaranteed crash-atomic directory transaction. The CLI does not fetch books, load a model, assign speakers, generate sound, or predict duration. It also accepts FB2 through the existing bounded importer.

## EPUB handling

| Area | Implemented behavior |
|---|---|
| Reading order | Resolve `container.xml` from the archive root and follow OPF spine order; do not reorder prose to match a malformed TOC ordering. |
| EPUB 3 contents | Read the declared navigation document's `toc`, including nested entries, relative targets and UTF-8 percent-encoded fragments. |
| EPUB 2 contents | Read NCX when no usable EPUB 3 TOC is available. |
| Several chapters in one file | Split at resolved TOC source anchors, including parent-section and empty-anchor locations. Repeated headings are a fallback only when that document has no usable TOC boundary. A document-level TOC chapter is not split merely because it has subheadings. |
| One chapter in several files | Join immediately adjacent, primary, heading-free documents without a new TOC target to the preceding TOC-backed chapter. Preserve all contributing file paths and passage locations. A new heading, TOC target, non-linear document or nonadjacent spine position prevents this join. A warning records the structural inference. |
| Introduction and unresolved targets | Retain text before the first chapter anchor. An unresolved fragment produces a warning and never causes the preceding prose to be discarded. |
| Optional material | Retain cover/navigation and non-linear sections for reading, excluding them from default narration. Users can include their narratable text explicitly. This is based on metadata, not semantic guessing about all front matter. Whole-document OPF guide types and EPUB 3 landmarks (`title-page`, `copyright-page`, `notes`, `colophon`, `index`, `bibliography` and similar), and body or top-level section `epub:type` values such as `titlepage`, `imprint` or `colophon`, also make a document optional. A guide or landmark entry with a fragment (`file.xhtml#id`) changes a document's role when the element with that ID contains every passage of the document, for example `toc.xhtml#toc` naming the body or a wrapper or `nav` around the whole page. For `toc` and `cover` it also does so when that element starts the document, no table-of-contents entry points to that document, and the document looks like that kind of page. A `toc` page has more than half of its narratable passages, headings included, linking to other documents; a note-style number link counts only when its passage is otherwise empty, a list number, or ends in a leader (`…`, `..`, `·`), as in chapter-number or page-number entries, so note markers glued to words do not count. A `cover` page has no narratable passage other than headings, so it holds only a title and figures. The element starts the document when no passage comes before it or it sits inside the first passage, for example `<h1 id="toc">`, `<a id="toc"/>` at the top, or `<h1><a id="toc"/>Содержание</h1>`. Other fragments do not change the role. This includes an inline table of contents, a chapter heading in a document that the table of contents points to, and the start of a document with body text, such as a title followed by an author line. A `text`/`bodymatter` entry, with or without a fragment, still keeps the file primary. If this metadata would leave no primary section with narratable text, the demoted documents that have narratable text stay primary. |
| Linked notes outside the spine | Retain referenced, declared local content documents after the original reading order as optional sections. Follow finite local links without duplicating or looping; do not scan arbitrary undeclared files or fetch external resources. |
| Internal links | Resolve local targets after final passage IDs are assigned. Retain note/backlink text and safe `data-source-link` IDs; expose click/keyboard navigation in the reader. Broken targets retain visible text but no active link. |
| Notes | Note references and backlinks stay visible and linked. Their text is left out of spoken text only when it is a marker: `1`, `[1]`, `(1)`, `{1}`, superscript digits, `*`, `†`, `‡` or a return arrow. A typed note link (`epub:type` noteref/backlink, `role` doc-noteref/doc-backlink, FB2 `type="note"`) also drops a single Latin letter, a Roman numeral of up to five `i`/`v`/`x` letters, a run of up to eight `*`, `†`, `‡`, `§`, `¶`, `‖` or `#`, and a number with a leading or trailing `*`/`†`/`‡` or a trailing period, each optionally in brackets. It also drops any other text of at most six characters without spaces that contains a digit or other numeric character, or that has no run of three or more letters other than a Roman numeral, for example `<1>`, `1.1`, `12a`, `1–3`, `n1`, `a.`, `ii.`, `Ⅳ`, Cyrillic `а`, `[б]` or `в)`. A typed note link around a real word (three or more letters that are not a Roman numeral), longer text or spaced text keeps its words. Endnote list items keep their visible list number (`1. `). Footnote/endnote items (`epub:type` or `role`) and paragraphs inside endnote sections are notes; a document whose body holds only such content, with optional headings, is an optional notes section. |
| Metadata and covers | Prefer Dublin Core metadata, retain multiple creators, and recognize EPUB 3 cover-image and EPUB 2 cover metadata. |
| Source structure | Preserve paragraph boundaries inside blockquotes/lists, inline emphasis, figure references and existing sanitized table/MathML/SVG handling. Source locations include EPUB path, DOM path, position and available anchors. |
| Scene separators | Retain horizontal rules and explicit glyph-row separators visually, but omit them from spoken inputs. A glyph row is a whole paragraph or heading made of three or more separator glyphs (`* * *`, `***`, `— — —`, `• • •`, `◆ ◆ ◆`, `~ ~ ~`, spaced `x x x` and similar) or a single `⁂`/fleuron. Such a heading is a separator, not a chapter heading, so it never splits chapters or blocks a continuation join. Empty spacer paragraphs and image-only ornaments are not promoted to separators. Carry structural scene boundaries into conversational casting contexts. |
| Fonts and encryption | Known IDPF/Adobe obfuscated resources declared as fonts are skipped with a warning; application typography is used. Encrypted reading content, unknown encryption and invalid encryption metadata remain rejected. No decryption is attempted. |
| Validation | Reject: duplicate or missing manifest IDs, missing primary resources, invalid content roots, unsupported primary media without supported fallback. Repeated/unknown spine entry: skipped, warning. Repeated anchor ID: first use kept, warning, links go there. Existing archive, entity, source-size, image limits remain. Unreadable archive entry (bad CRC, broken compressed data, unsupported compression), images included: import fails, `damaged_book_entry` (`EPUB entry <path> is damaged and cannot be read.`). Markup counted during parse, before any tree use: ≤200,000 elements, ≤400,000 attributes, ≤400,000 text runs per book (EPUB container, package, navigation, content summed; FB2 whole file); excess stops parse, whole book fails `book_markup_limit`. Depth >256 stops parse. Document declaring own XML entities and using one: refused before parse. Content document not valid UTF-8/UTF-16 and without XML encoding declaration that decodes it: `invalid_book_encoding` (`The text encoding of book document <path> could not be read.`); HTML `meta` charset not used; no replacement characters imported. Not-well-formed content document: re-read with libxml2 HTML parser (knows void `img`/`br`/`hr`, implied paragraph ends); kept only when parsed text = source text (tags removed, entities decoded, whitespace ignored), every paragraph-level start tag (`p`, `h1`–`h6`, `li`, `dt`, `dd`, `div`, `blockquote`, `pre`, `table`, `tr`, `td`, `th`, `figure`, `hr`, `br`, `img`) became an element, source has `html` or `svg` element, no unknown named entity; warning names document. Else original `invalid_book_xml`. CDATA or text after `</html>` → malformed document fails. Image that cannot be shown: alt text becomes passage text only when descriptive; empty, file-name-like (`img_0001.jpg`, `Image 3`) or equal to image file name → nothing narrated. ZIP names without UTF-8 flag read as UTF-8 when valid UTF-8. Decoded image types: PNG, JPEG, GIF, WebP, BMP; others skipped, warning. Inline SVG omitted, warning, when one kept geometry attribute >32 KiB or book's kept SVG geometry >8 MiB. |

## FB2 handling

| Area | Implemented behavior |
|---|---|
| Encoding | Leading whitespace before the XML declaration is ignored. A file without an encoding declaration that is not UTF-8 is scored as Windows-1251 and as KOI8-R, or as KOI8-U instead of KOI8-R when its KOI8-U reading has Ukrainian letters (`і`, `ї`, `є`, `ґ`) next to other Cyrillic letters. A candidate is plausible when at most 5% of the letters in its non-ASCII words sit in malformed words (mixed scripts, a capital after a lowercase letter, non-Cyrillic letters; all-capital Cyrillic words are ignored) and 30–60% of the letters in well-formed Cyrillic words are vowels. Its score is the share of non-ASCII characters that are frequent Russian letters (`о е а и н т с р в л к м д п у`) in well-formed words. The winner must score at least 0.5, lead the other candidate by at least 0.3 and decode without undefined bytes; otherwise the import fails, so Western European, Mac Cyrillic, CP866 and ISO-8859-5 files are refused instead of imported as garbled text. An unknown declared encoding, bytes invalid for the declared encoding, a mostly UTF-8 file with stray invalid bytes and a refused undeclared file fail with code `invalid_book_encoding` (`The book text encoding could not be read.`); XML errors keep `invalid_book_xml`. |
| Language | A missing or empty `<lang>` is recorded as `und`. Codes and names are matched by their leading word in any case: `ru`, `ru-*`, `rus`, `Russian`, `русский` are Russian; `en`, `en-*`, `eng`, `English`, `English (US)`, `английский` are English. Fallback chapter titles are Russian for Russian, and for a value that is missing, `und`, `mul`, `mis`, `zxx` or not a language tag when the text is mostly Cyrillic. EPUB fallback section titles use the same name matching without script detection. The speech language of both formats uses it too: a Russian or English value yields to the other language when the text is mostly that script, an unknown value uses the text script, and a well-formed tag of another language (`de`, `uk`) gives `Auto`. Each generation pins its speech language when it first renders, so a later change to this rule or to the book metadata does not change it (see [ARCHITECTURE.md](ARCHITECTURE.md)). |
| Sections | Each section with text is a chapter. An untitled nested section, a section titled only with a separator glyph row, and text after a nested section are named after the parent section with a running number that counts only the parent's own pieces, for example `Глава 3 (2)`; a titled child section that opens with the parent's heading counts as the parent's first piece. Untitled top-level sections keep localized numbering. A top-level section titled only with a separator row is named by that row and the first six words of its first paragraph, for example `* * * Я помню чудное мгновенье:`. |
| Empty lines | `<empty-line/>` is a scene separator only as a direct child of a section between two paragraphs. The spacing style is decided once per book: single empty lines are paragraph spacing only when the whole book has at least 30 gaps between adjacent section paragraphs and at least 90% of them are single empty lines. Then single empty lines are spacing in every section, short ones included, unless that section has adjacent paragraphs without an empty line and fewer than 90% of its gaps are single empty lines. Runs of two or more empty lines always stay separators. A book below that threshold, such as a short work with one-paragraph scenes, keeps single empty lines as separators. Elsewhere (citations, epigraphs, poems, titles, annotations, section edges, inside a paragraph) it is spacing or a line break. |
| Text lines | `<subtitle>` is a heading unless it is a separator glyph row. Poem and epigraph `<text-author>` and `<date>` lines are separate passages. Inline `<style>` text is kept for any FictionBook namespace. |
| Metadata | Authors use first, middle and last names with collapsed spaces, or the nickname when those are empty. An empty `<book-title>` gives `Untitled book`. |

## Source fidelity and narration boundaries

The original uploaded file is preserved byte-for-byte. The prepared representation intentionally sanitizes active content and normalizes whitespace/Unicode using the existing import policy. It is not a byte-for-byte rendering of the publisher's XHTML/CSS. Prepared text drops invisible format characters (zero-width spaces and joiners, word joiners, byte-order marks, direction marks and similar); the reader display keeps them. A paragraph that is a single capital letter is treated as a separated drop cap and joined to the next paragraph only when it carries a drop-cap hint and the next paragraph starts with a different lowercase letter. A hint is a `class` or `epub:type` value such as `dropcap`, `drop-cap`, `initial`, `initial-letter`, `first-letter`, `lettrine`, `cap` or `capital`, or an inline style with `float: left`, `float: right` or `initial-letter`, on the letter element, an element inside it, or a wrapper that holds only that letter. CSS values such as `text-indent: initial` and classes such as `para-initial` are not hints. Whitespace at the start of the following paragraph is kept as one space only when it has no line break, for example `<p> тот вечер`. Whitespace that contains a line break is source formatting and is removed, so a split word joins (`Т` + `ак` gives `Так`) in both the reader and the narration; in such pretty-printed sources a one-letter drop-cap word also joins the next word. One-letter lines without such a hint, including FB2 verse lines and words such as `Я`, `I` or `О`, stay separate. Adjacent inline spans without whitespace are not separated, because the source does not say whether a space was intended.

Every pre-analysis segment records a contiguous Python-codepoint range into its prepared passage. Concatenating those segments reconstructs that passage exactly. The current cap remains 420 codepoints. A cut prefers the last sentence end, then the last clause break (comma, colon or spaced dash), then the last space, all after the first third of the window. A period after a single letter (initials, `т. е.`) or after `гг`, `им`, `см`, `стр`, `др`, `ул`, `ст`, `Mr`, `Mrs`, `Ms`, `Dr`, `St`, `etc` is not a sentence end, and neither is sentence punctuation followed by a lowercase letter. A cut without any break never separates a letter from its combining marks. Saved segments of existing generations are not re-split; coverage validation is per passage, so their boundaries stay valid. This is not phonetic normalization or proof that a speech model will pronounce the text correctly.

The same source-segment function now supplies Store generation creation, job analysis and the CLI, reducing duplicated boundary logic. The report's segment count describes these initial inputs: character attribution can split them further. No fabricated audio duration is shown.

All primary reading chapters are analysed for casting even when only one is selected for rendering. Optional sections are analysed only when explicitly selected. Full-book context therefore means the primary reading text plus requested optional content, not an automatically narrated table of contents or all footnotes.

One narrator still has a reusable repertoire; no book-wide uniqueness requirement was introduced. Explicit scene separators reset the existing structural conversation grouping. This is not a semantic scene detector: a standalone narrator paragraph can still split a real conversation.

## Persistence and compatibility

The library uses SQLite schema 4; opening a saved manifest does not reimport it. Existing stored book manifests are not reimported or rewritten on opening. Older manifests receive a computed preparation report in the response only; saved chapter identities, casting, generations, audio and exports are retained. Existing imports do not automatically acquire the new chapter segmentation.

New imports store preparation schema 2, including formatting hints. Additional chapter/block fields describe optional content, navigation and source locations. Casting checkpoints use schema 5: schema 3 made structural scene identity part of the input, schema 4 stores trait evidence per value, and schema 5 stores analysis over numbered passage units with character kind votes. Incomplete older analysis is repeated before a new cast is frozen; already-complete casting is retained. Model-pack fingerprint rules are unchanged. The speech cache key is schema 3; passages that already have audio keep their stored key, and unrendered passages can reuse audio saved under the earlier key when the generation's speech language equals the earlier language rule or the pack uses `auto` language mode, as described in [ARCHITECTURE.md](ARCHITECTURE.md).

## Rich-content handling

SVG cover images retain safe geometry and local asset identifiers. An exact contents-label match on the first non-figure passage can identify a chapter heading stored as a paragraph without changing its words. A cover section without a contents label or heading is titled with the localized cover name, not the document title. Supported enclosing code, quotation and emphasis formatting survives extraction and is included as bounded analysis hints. Formatting does not assign a speaker or an emotion.

## Limits

This is a bounded lxml-based importer, not Foliate-js or a complete EPUB reading system. Publisher CSS, fixed-layout fidelity, scripts and remote resources are not rendered. Malformed XHTML accepted only through lossless HTML re-read (Validation row); entities needing external DTD still rejected. Known font-only obfuscation is skipped; encrypted reading content is rejected.

A contents anchor inside a paragraph maps to the whole passage, not an arbitrary inline cut. Chapter continuations are structural inferences recorded as warnings. Unlinked superscript digits are retained because they can be exponents; no automatic note-reading or speech-normalization policy is implied. Internal navigation is passage-level, not a precise EPUB CFI.

Preparation performs no character assignment, speech synthesis, alignment or duration prediction. Verification commands are in [VERIFICATION.md](VERIFICATION.md); overall implementation limits are in [../STATUS.md](../STATUS.md).

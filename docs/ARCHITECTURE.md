# Current architecture

## Boundaries

React is the view layer. Rust owns the desktop process lifecycle and native export destination. A standard-library Python HTTP service owns the local SQLite library and long-running operations. All service requests require a random per-launch bearer token and an accepted local origin. Native commands do not expose a general-purpose shell. The main window navigates only to the application's own pages; other navigations, such as a dropped link or file, are cancelled. Native export copying and reads of OS-opened books run off the main thread.

The service is bound to IPv4 loopback only. Its OS-level library lease is acquired before SQLite startup and prevents a second core from resetting or modifying an active library. A core that fails before its handshake, for example because the library is open in another process or comes from a newer version, prints one JSON line with the error and exits; the shell shows that text in its startup dialog. The core and its worker processes exchange UTF-8 JSON regardless of the system code page: the shell starts the core with `PYTHONUTF8` and `PYTHONIOENCODING`, the core passes them to its workers, and the workers reconfigure their standard streams. EPUB content is sanitized and rendered as local markup, not opened as a privileged Tauri page. File access uses application-owned IDs and allowlisted asset lookups. No book content chooses model paths, executable arguments, or internet endpoints.

The importer intentionally does not preserve executable content. It rejects encrypted EPUB reading content, path traversal, oversized expansion, and external XML entities. Markup counted during parse: ≤200,000 elements, ≤400,000 attributes, ≤400,000 text runs per book (EPUB: all XML documents summed; FB2: whole file), depth ≤256. First excess stops parse, whole book rejected (`book_markup_limit`), never truncated. Malformed XHTML: re-read with libxml2 HTML parser, kept only when all character data and paragraph-level tags survive, else `invalid_book_xml`. Undecodable document: `invalid_book_encoding`. Unreadable archive entry: `damaged_book_entry`. Image that cannot be shown: alt text read only when descriptive; empty, file-name-like (`img_0001.jpg`, `Image 3`) or equal to image file name → nothing. Remote images are not fetched. The original upload is retained unchanged even when the reading representation is normalized. Repeated EPUB references to the same normalized image path share a decode result, including the cover. Converted PNG assets carry their stored byte size and share a 250 MiB aggregate limit; identical output assets are not counted twice. This limit is for saved converted assets, not a bound on total process memory. Markup limits bound parsed tree, not total memory. Measured: 199,000-element FB2 peaks 252 MiB (one paragraph) / 292 MiB, 3.4 s (99,500 paragraphs). EPUB source paths built in one linear pass (same strings as lxml `getpath`, which was quadratic over siblings: 132 s before); FB2 builds no source locations. Existing per-entry, pixel-count and archive-expansion checks remain.

## Canonical source model

A book has an immutable source file, ordered chapters, and stable paragraph/figure/equation/table IDs. Speech segmentation preserves exact source ranges using Unicode codepoint offsets. The original, normalized reading representation and spoken text remain separate.

The bounded source importer is smaller than a complete EPUB engine. It is not Foliate-js. The current reader is a reflow document, not a claim of complete EPUB3 rendering conformance.

## Analysis and automatic casting

Every requested generation first analyses all primary reading text plus selected optional sections, even for a chapter-only audio selection. Analysis and casting are not reused by later generations of the same book. The application pre-splits every target passage into numbered units with the shared boundary module. It cuts after sentence ends; before an em dash, en dash or hyphen-minus that is followed by a space and follows a comma, sentence-end mark or colon, with or without whitespace between them; before every other em or en dash that is not inside a word or attached to an interrupted word; before opening quotes and after closing quotes; at guillemet-span edges and at ASCII-hyphen attributions. `«`, `„` and `‘` always open and `»` and `’` always close; `“`, `”` and the ASCII `"` open at the start of the passage or after whitespace or an opening bracket and close elsewhere; `‘` and `’` between two letters are apostrophes and do not cut. Trailing whitespace stays in its unit, and a unit without letters or digits joins its neighbour. Candidates are never joined or dropped to fit a context; a passage too large for one request is a capacity failure and is held. The model receives the units, not codepoint offsets, and returns parts as inclusive unit ranges (`first`, `last`) that must cover every unit in order. Nothing is snapped; stored segments keep the exact codepoint offsets of their units. Requests also carry up to two neighbouring context passages on each side within the same scene, with the speaker ranges already accepted for them, and a projected character registry of at most 40 entries: characters whose name or alias occurs in the targets or context, compared in the canonical forms used for reconciliation so that inflected forms match, then accepted context speakers, then recent speakers of the chapter, then the characters with the most speech. Detailed entry: ID, name, aliases (every alias matching request text first, all kept, up to the 30 stored; then others up to 12 in total), description cut at word boundary to 300 chars. No evidence, kind or traits — reply cannot echo stored votes. Request short of room (measured with model tokenizer, below output limit described below): worker lists as many entries of that order as fit in compact form (`more_known_characters`: ID, name, every alias matching request text, then others up to 3 aliases), then gives descriptions to largest prefix of listed entries that still fits. Every listed ID = valid speaker and character ID in response schema. Worker returns reply plus the IDs it actually offered (listed entries + accepted context speakers); runtime validates and resolves speakers against those only, so an ID pruned for room is rejected even when grammar is bypassed. Multi-target batch: must list at least mentioned characters + accepted context speakers (count sent as `required`) and keep room for full output limit, else capacity failure, batch bisected. Single target: lists largest prefix that leaves room for output limit, none when even empty registry leaves less; capacity failure only when empty registry leaves less than estimated output. Measured 2026-10-05 (Qwen3 Hugging Face tokenizer, one Russian novel, 8192 context, synthetic entries): compact entry ≈54 tokens; median request lists 27 of 40, all 40 in 47 of 245 requests; median request gets no descriptions. Provisional: description-versus-coverage trade-off not accepted for production before real-model evaluation (release gate). Accepted context speakers are hints; target passages still need their own evidence.

The default analysis provider is `auto`: use an installed Codex CLI first, then an installed Claude Code CLI, and use the sealed local model only when neither CLI is available. The automatic choice is resolved and pinned when a generation is created, so one book cannot silently switch providers partway through analysis. Users can also select Codex, Claude, or local analysis explicitly. CLI calls use the user's existing authenticated subscription, run noninteractively with bounded JSON schemas, and have no enabled tools. The local speaker fallback makes two independent passes and retains a speaker suggestion only when both passes agree. Because its measured precision remains too low for silent acceptance, every model-resolved local speaker stays in review; strict text attributions remain automatic. A disagreement or repeatedly invalid answer is also a review hold. It does not silently substitute narrator. The local fallback remains offline.

The provider order is measured on the frozen speaker-resolution benchmark in `training-work/speaker-resolution-eval-qwen35-v1/`. On its untouched partition, Codex plus deterministic rules resolved 896/912 spans and Claude resolved 892/912. The local agreement gate accepted 781/908 modeled spans at 72.60% precision and held the other 127 for review. Running both CLIs on every span is not the default: their agreement gate raised accepted precision only to 98.55% while doubling CLI work.

### Progressive chapter analysis

The progressive policy is being evaluated rather than assumed. Current results are
recorded in `docs/PROGRESSIVE_ANALYSIS_BENCHMARK.md`. Generic voting and a final
high-effort recheck did not improve the frozen test. The only exploratory gain came
from a normal-effort Codex pass that received the complete chapter: 154/162 became
159/162 on three contiguous late chapters, with no introduced speaker errors. A
separate locked-identity evidence repair fixed all ten invalid source quotes. These
findings require prospective validation on another book before automatic rollout.

Full-book preparation should use listening time as an analysis budget. Chapters are
processed in reading order and a chapter receives at least three distinct checks:

1. shared speech structure and exact source boundaries;
2. primary character, voice-family and delivery analysis with the accumulated cast;
3. an independent critic pass over uncertain or structurally complex decisions.

Later chapters may receive up to three more background checks before the listener
reaches them: cross-chapter character continuity, an alternate-provider check for
disagreements, and final adjudication. These are different jobs with different
evidence. Repeating the same deterministic prompt does not count as another pass.
The pass budget grows from three near the playback cursor to as many as six farther
ahead, where preparation has more wall-clock time. A seek reprioritizes the target
chapter and completes its minimum three-pass gate before playback.

Extra passes operate only on unresolved, low-confidence, structurally complex, or
cross-chapter inconsistent spans. They preserve every proposal and its provenance;
the last answer never silently wins. Agreement can raise confidence, disagreement
creates an adjudication or human-review item. The local provider remains a review
suggestion even after repeated agreement until a measured frozen evaluation shows
that the new policy is accurate enough.

A chapter can be rendered once its minimum gate is complete and its used character
voices are frozen. Analysis then continues ahead of playback. A later alias merge or
speaker correction invalidates and requeues only affected rendered segments. It
cannot rewrite already accepted human labels or unrelated audio.

Speech structure is a separate, shared first stage in `runtime/rimsky/speech_structure.py`. One boundary module (`runtime/rimsky/boundaries.py`) creates every candidate: sentence ends, the feature dash rule, every non-word-internal em or en dash, quotation edges, guillemet spans and ASCII-hyphen attributions. Analysis units split at all of them; structure chunks are units joined across sentence-only cuts, so a fixed structure is always expressible as unit ranges. The model may classify each chunk only as character speech or narrator prose. Local staged analysis and both CLI providers use the same prompt, candidate builder, response validator and persisted `{target_id: [{index, start, end, text, mode}]}` shape; the full-analysis request receives it as `fixed_speech_structure` unit ranges, and the central validator rejects a target whose parts contradict a fixed mode or merge separate speech turns. Candidate construction preserves every source character and does not split numeric ranges, word-internal dashes, or interrupted words. Speaker identity and mood are later decisions and cannot rewrite these offsets.

The frozen Book 2 labeling board remains on its existing compatibility plan so its reviewed choices and immutable split overlay are not migrated during this refactor. New production analysis uses the shared component. A future comparison against Book 2 must preserve its current labels and exact audio cuts.

Text structure and a narrator's recorded performance are separate evidence. A listener may identify an audible change that is absent from the text structure; corpus tooling records that later as a `performance_split`, without teaching the structural parser that every such performance choice is a textual speaker boundary.

The speaker resolver will be evaluated against a frozen human-reviewed gold set: Book 1 reviewed character IDs plus a hand-checked Book 2 sample stratified across deterministic, local-model and escalated cases. Model output cannot serve as its own reference. For attribution rules, “explicit” is narrow: a registered name or alias in the same paragraph immediately after the dash ending the speech span. Pronouns, lead-ins from an earlier paragraph, and names occurring inside spoken words still require resolution. Broken-dialogue-pattern escalation is measured separately and is retained only if it changes enough answers to justify its review cost.

The implemented resolver runs narrow named attributions before the local model. A deterministic attribution must reduce to a speech verb, no more than two adverb modifiers, and one registered name or alias; no pronoun and no negation or hearsay particle (не, ни, якобы, будто, словно, вроде, бы) may precede the name, and a comma, `на что`, or `и` ends deterministic inspection. Other names remain recorded model hints. If the local answer disagrees with one of those hints, the case escalates instead of becoming a silent fixed answer. Adjacent speech chunks after sentence-ending punctuation are separate turns even when both structure modes are `speech`; both the staged path and the full-analysis validator enforce that boundary. The local model handles other speech. It records escalation provenance for unresolved answers, attribution-hint disagreements, duplicate new-character names, resumed-speech disagreements, adjacent speech turns and long unattributed exchanges. New generations may select a Codex CLI tie-breaker for those cases; without one, the local answer remains visible in the speaker review queue. Resolution metrics report the unattributed-exchange trigger separately, including how often the tie-breaker changed the answer.

The unresolved-generation default is `hold_flagged_segments`: render the rest of the book while holding each unresolved segment and its direct neighbours (same chapter) as marked gaps with segment status `review`. Held segments are never rendered as accepted audio, never counted ready or damaged, and the generation ends with status `held` instead of `ready`; complete export is refused while it is held. Holds come from review records in `analysis.speaker_resolution`: local-model speakers, staged neighbour-only evidence (`neighbor_only_evidence`), unknown speakers (`unresolved_speaker`), degraded targets (`degraded_analysis`, with reason), and ambiguous or provisional presentation-voice mappings (`presentation_review`). A passage whose synthesis reaches the speech model's generation cap is held (`backend_holds`) without clipping its text and is not re-rendered until its spoken text changes. A user speaker correction to a real character, or an explicit `confirm_speaker` verdict, resolves the overlapping review records in the new narration revision and recomputes the held set. Cast review operations never release holds. `render_with_warning` renders held passages only as a marked narrator-voice preview; the generation still ends `held`. For future context-assisted split synthesis, the generation text retains the comma and dash; a crop is accepted only inside detected silence of at least 60 ms after the aligned final word. Missing silence causes regeneration or a raw-fragment fallback, and both fallback rate and added generation time are reported.

Synthesis units are sentence-sized (`analysis.synthesis_units`): consecutive sentences with the same speaker, delivery and context are grouped up to 420 characters, never across a trailing ellipsis or a heading, and a sentence is never cut. Every model part is kept in `segment.performance.analysis_parts`. A sentence whose parts differ in speaker, delivery or context (`internal_transition`) is never flattened to its dominant voice: each part is rendered with its own voice, delivery and presentation channel, and the part WAVs are concatenated into the segment audio (composite render key over the part keys). Such a segment never reuses flattened legacy-key audio, and an edited spoken text that can no longer be split into parts holds the passage instead of rendering it with one voice. The displayed segment speaker is the unknown part when any part is unknown, otherwise the character with most text. A human verdict can be given for the whole segment (it then covers only the parts spoken by the shown speaker) or per part (`{id, part, speaker}` / `{id, part, confirm_speaker}`); records over other parts stay held. Alias merges and cast-review merges rewrite part speakers together with segment speakers. Before rendering, unknown or degraded speech of an older analysis without review records receives `unresolved_speaker` / `degraded_analysis` records, so it is held rather than narrated; accepted audio of complete older generations is never re-rendered or relabelled. A character known only by a descriptor (no proper name or alias in book-vocabulary terms, such as `охранник` or `гуманоид`) is scoped to the chapter scenes where it was first established (`scopes` on the character record); speech attributed to it in another scene is held (`descriptor_identity`) instead of accepted, because a reused descriptor often names a different person. Older characters without `scopes` are unaffected. Repair never resets a held passage. Export of selected chapters is refused only when a selected passage is held. A superseded incomplete analysis checkpoint is written losslessly to `superseded-analysis/` in the library (outside the startup-cleaned `work/` folder) before analysis restarts under the current contract.

Every committed analysis batch passes three separate jobs: the speech-structure pass (CLI providers, staged local analysis and single-pass local analysis alike; single-pass local requests carry the fixed structure as unit ranges), the primary analysis, and an independent critic job (`critique`, `runtime/rimsky/critic.py`). The critic sees units, the fixed structure and the primary roles and speakers, never the primary evidence, and must review every part. Its character list is the registry as it was before the primary answer: model-written descriptions are passed only as `unverified_summary`, characters first proposed in the same pass are marked `new_in_this_pass` without any summary, and continuity comes from up to two raw source anchors per character: complete earlier passages that analysis cited for it, never clipped, with source block, character range, chapter and scene. An oversized critic request is subdivided and an indivisible one is held (`critic_unavailable`). Anchors may be cited, but a character speaker is supported only when the review cites the target passage itself; a summary can never be cited. A disputed role or speaker, a character speaker supported without the target's own passage, or a critic answer that is still unusable after one targeted re-ask holds the part (`critic_disagreement` with the critic's proposal and reason, or `critic_unavailable`); agreements are retained as `critic_agreement` records. Each contiguous run of reviewed passages gets its own preceding and following context passages in reading order, also after a capacity split, which reviews each passage with its own neighbours (including other passages of the batch). A review is contradictory, and is re-asked once and then held, when it supports a speaker but names a different alternative, disputes a speaker but names the same one, or disputes a role while proposing the same role. The review of every part, narrator parts included, is retained in `analysis.critic_reviews` (role and speaker flags, alternative, evidence, reason). A critic capacity failure on a single passage holds it. Infrastructure failures of the critic fail the generation like other worker failures. Repairs and retries never count as the critic pass. The batch checkpoint is written only after the critic, so resume never skips it. Accepted-speaker hints for later requests (`accepted_speakers` in context passages, given to the primary, the blind second provider and the critic) and the speaker-driven registry priorities (recent speakers and speech volume) come only from trusted parts: `store.trusted_inputs` drops every part whose own range carries an open identity review (provider, critic, descriptor, local, unresolved, degraded or agreement holds; presentation and backend holds do not concern identity), unless human identity verdicts with the same speaker cover that exact range segment by segment and part by part; a verified prefix keeps only its own range trusted and never promotes a held suffix. They are published only after the batch's critic, and `Jobs` rebuilds them from the persisted resolution records and verdicts on resume. The complete `casting_inputs`, raw passages, proposals and review records are kept unchanged for casting, rendering and review.

Verdicts are concern-specific: identity verdicts (`confirm_speaker`, speaker changes, segment or part level) release identity holds only; presentation holds need `confirm_presentation` (segment or part), which binds the effective voice, base voice, channel, register, confidence, evidence, part range and pack fingerprint recorded in `performance.presentation_binding`; any change of those inputs re-holds the passage. Backend-limit holds are never released by verdicts.

The renderer performs the supported parts of the performance plan: planned pauses (`pause_before_seconds`, `pause_after_seconds`; headings and trailing ellipses) are inserted as silence around the segment audio and are part of the composite render key, and pace / ending pace reach a CustomVoice pack with `instruction_control` as part of the TTS instruction and of the part render key. A pack without pace control never renders a planned pace as the default: the passage is held (`performance_capability`, not releasable by identity or presentation verdicts) and the generation reports one `pace_not_supported` notice. Mixed sentences get one timing plan: the outer segment pauses plus an interior pause at each part junction (the larger of the earlier part's pause after and the later part's pause before, e.g. an interior ellipsis), all written as exact silence samples and included in the composite key. Accepted takes keep their saved audio.

Only typed analysis-capacity failures trigger ordered bisection into smaller target batches. Each accepted batch records its completed source IDs with the character registry and source-bound casting inputs. Resume skips those sources even when an interrupted parent batch was split differently. Invalid annotations retain strict validation; no source is dropped and a single target that cannot fit fails explicitly. Alias reconciliation remains a separate whole-registry context-limited operation.

Validation is per target, and every reason names the passage. The response schema limits speakers to `narrator`, `unknown`, the IDs of the registry entries actually sent, the speaker IDs accepted for the context passages and the temporary IDs `new_1` to `new_40`, and limits character record IDs to the same known and temporary IDs. Runtime validates reply against same schema itself, grammar or not, before any merge; nothing coerced. Character records: required fields, types, enums (kind, trait values, offered/temporary IDs `new_1`…`new_40`), evidence IDs from targets/context only, size limits, no unknown fields; any failure → every target of batch invalid, reason names field, re-asked. Top level: only `characters` + `passages`, ≤40 records, passages ≤ targets. Each passage checked same way (speaker exempt: slip resolution below) → only that target invalid. Trait value with empty evidence stays schema-valid → unknown. Validation resolves a speaker to an exact ID first, then to a case-insensitive match of `narrator`, `unknown`, a known character ID or a temporary ID listed in the reply, then to a display name that matches exactly one known or newly created character. A target is invalid when its parts do not tile its units, name a speaker that does not resolve, use an unknown delivery or malformed evidence, or, for a part with a character speaker or non-neutral delivery, do not cite the target's own passage ID; that ID is never added automatically. A reply that is not a JSON object makes every target of its batch invalid. Character records are built only from evidence in the valid targets and the context. A new character needs a valid target as evidence; when its own evidence cites none, the valid targets with a part that speaks through its temporary ID and cites the target's own passage ID become its evidence. A new character with neither is dropped, a name, alias or trait update of a known character that cites only invalid targets is not applied, and a valid target whose part speaks through a dropped record becomes invalid with its own reason. This check repeats until no further target fails. Valid targets are committed together with the remaining character updates. Each invalid target is asked again alone, once, with its own reason. The re-ask carries the exact reason and, as untrusted data, only that target's rejected passage object plus the character records its parts use (`previous_rejected_answer`); a local request that cannot fit them omits them explicitly (`previous_rejected_answer_omitted`) instead of shrinking source, structure or registry. Rejected content is never evidence or a vote. A target that is still invalid, or a single target that exceeds the model capacity, is degraded: it becomes one part with speaker `unknown` and neutral delivery, its warning is `Speaker analysis failed for this passage; held for review.`, `analysis.degraded` records its ID and reason, a `degraded_analysis` review record holds it, and preparation continues with the other passages. Every part must also carry `context` (mood, channel, content register, confidence and exact contiguous quotes from supplied passages); a quote that is not verbatim makes only that target invalid. A neutral delivery is upgraded from the context mood only when that context cites the target's own passage. Capacity failures and timeouts of a multi-target batch bisect it in order. Transport failures have their own error type (`exit`, `timeout` or `protocol`) and are never sent to the model: an exited or protocol-broken worker is restarted and the request repeated once, and any other worker error fails the generation. A timeout restarts the worker, and a timed-out single target is asked once more. A second timeout in a row, in analysis or in alias comparison, fails the generation with the timeout message; any other outcome of a request in between resets the count. Every target of a timed-out analysis request gains one count in `analysis.timeouts` (target ID to count), which is saved at once and kept when the generation fails. When a later run starts, every unfinished target with at least two counts is sent alone, and a timeout of its request is not retried; if that request times out and the request before it did not, the target is held (`degraded_analysis` with the timeout message as its reason), never narrated. A generation stopped by one passage that always times out therefore gets past it on the next resume, while a backend that stops answering still fails the generation at the second timeout in a row. When the worker cannot be restarted, the generation fails with the original message. The worker measures the room left by the configured context minus the tokenized prompt and a 128-token margin. The estimated output is 320 tokens plus 48 per target and 64 per unit (parts carry context), and the output limit is twice the estimated output but at least 3,072 tokens; the registry is shortened against both as described above. `max_tokens` is therefore the output limit for every multi-target request, and for a single target the smaller of the output limit and the room left with an empty registry, however many optional entries were offered; a reply that reaches it is a capacity failure. Batches are bounded by 7,000 characters, an estimated output of 3,072 tokens, and chapter and scene. The response schema enumerates passage IDs, unit numbers, speaker IDs and character IDs and bounds every list and string: at most 16 evidence IDs, 40 characters per reply, 30 aliases, and fixed name, alias and description lengths. Each accepted batch records its completed source IDs with the character registry and source-bound casting inputs. Resume skips those sources even when an interrupted parent batch was split differently. No source text is dropped.

Batch results and the character registry are committed together. A new character needs at least one valid target passage as evidence, cited or voiced as described above. Its stable ID is derived from its name, its first valid target evidence, its temporary ID and the batch; a collision with an existing ID gets a counter, so different characters are not merged silently. Temporary IDs of one reply never joined by matching names (`Петров`, `Петрова` stay two); only alias reconciliation merges. An existing character returned without current target or context evidence is not updated, and passage parts can still name it. Name or alias accepted only when it occurs (canonical reconciliation forms) in a passage the record itself cites. Known character's new label and new character's alias must also belong to no other character; new character may share a name. New character with no accepted label → unusable; only name fails → first accepted alias becomes name. Accepted label keeps ≤4 supporting passage IDs (`labels`). The display name follows specificity: a proper name replaces a descriptor, and a longer name that contains the current one replaces it; the other name stays as an alias. A single-word label never replaces a single-word name of at least 4 letters when it starts with that name minus its last letter, such as `Верочка` or `Willy` for `Вера` or `Will`; it becomes an alias. A name counts as proper when one of its words is capitalized and is not book vocabulary (ё read as е; the vocabulary comes from all analysed text). A word form is book vocabulary when the book writes it more often in lowercase than capitalized (a capital at a sentence or line start counts half, because it is weak name evidence), unless the book writes it in title case mid-sentence at least 3 times, or it is a full name listed in the name table used for reconciliation (below) or a case form of one of that table's diminutives. Mid-sentence means not the first word of a passage, no `.`, `!`, `?`, `…`, `:` or line break since the previous word, and not directly after `«`, `„`, `“`, `‘`, `"`, `'`, `(` or `[`. The articles `the`, `a` and `an`, and a word followed, after only whitespace, by another capitalized word, as in `Captain Hale` or `The Times`, never count as title case mid-sentence; so verse lines or two-line headings that import joins with spaces, and an honorific before a name, do not make `The` or `Captain` a name. A capitalized descriptor such as `Незнакомец` that the book mostly writes in lowercase, and in title case mid-sentence fewer than 3 times, therefore yields to a revealed name. `Вера` or `Will` written in title case mid-sentence at least 3 times, as in `сказала Вера` or `said Will`, is a proper name, so another single-word name does not replace it, although `вера` and `will` are mostly lowercase words there. Only exact word forms count, so a descriptor still counts as a name when its own form is not mostly lowercase in the book, even if its other case forms are. Aliases are capped at 30 per character; longer lists are truncated, not rejected. Kind (`person`, `mechanical`, `collective`; else person) counted like a trait: accepted record adds its supporting passages to `kind_support`, one vote per unique passage — repeat about same passage adds nothing. Older `kind_votes` and cast-review votes still count. The kind with most votes wins, and a tie is `person`.

Character reconciliation compares only candidate pairs. Names and aliases are folded (NFKC, case folding, ё→е, combining marks removed except the breve of й) and Russian case endings are stripped. The canonical form also joins forms with a fleeting vowel (Павел/Павла, Лев/Льва, Отец/Отца, Боец/Бойца, Санёк/Санька) and the case forms of nouns ending in -ай, -ой, -ая and -ея (Николай/Николая, Герой/Героя, Аглая/Аглаи, Пелагея/Пелагеи). A table maps the whole case forms of common diminutives (Саша, Сашей, Коли) to full names, not stems they share with other words, and only inside a name or alias that contains a capital letter. Inside other name, a word also matches own prefixes keeping ≥4 letters, dropping ≤3 (`Комар`/`Комаров`, `Will`/`William`) — not for patronymic forms (-ич, -овна, -евна, -ична): `Иван` no candidate for `Мария Ивановна`. Prefix-only pairs come after all other candidates, use only comparisons left under limit. A pair is a candidate when such a form of a whole name or alias of one character occurs as whole words inside a name or alias of the other. Each character contributes at most 31 phrases; a phrase longer than 6 words is indexed only as a whole, and variant forms apply only to parts of up to 3 words. Pairs are ordered by the rarity of their shared phrase, then by its word count; for each phrase, pairs of two speaking characters come before pairs with one speaker, and pairs of two silent characters come after all others. Both characters need evidence passages. A pair is not compared when both characters have a known gender, the genders differ and their folded names are not identical; such a pair is never replayed from saved decisions, does not count toward the comparison limit, the progress total, the skipped pairs or the unmerged pairs, and gives no same-performance hint. Whole groups checked before every comparison and union: member of one group with known gender opposite to member of other (folded names differ) → groups never compared or joined, pair counts neither as unmerged nor as same-performance hint. Unknown-gender character cannot bridge man and woman. Each pair is sent alone with the evidence passages of both characters, alternating between them and trimmed to fit the context. The model answers whether they are the same person; a merge must cite supplied passages from the evidence of both characters, and only those passages. A merge always goes into the character registered first, so chained merges cannot form cycles. The merged display name follows the proper-name rule above with the vocabulary of all analysed text, so a revealed name replaces a capitalized descriptor even when the descriptor belongs to the character registered first. Sharing a dialogue context does not block a merge. Before two merged groups are joined, the most specific name of each group (the name with the most words, then the earliest character) is compared: when neither stemmed name contains the other and those two characters were not compared yet, they are compared directly, and the groups are joined only if that answer is also the same person. This stops a short shared name, such as a family name, from joining two different full names. An answer that two characters are different blocks every later merge between their groups. An invalid answer is retried once with its validation error; a second invalid answer fails the generation and freezes no cast. A pair that does not fit even with one passage per character, whose answer reaches the output limit, or that times out once stays unmerged and is never sent again, while a second timeout in a row fails the generation; when the direct check between two groups fails this way, later pairs between those groups are skipped. The capacity notice counts distinct pairs of final characters that stay separate and were not judged different. At most 256 comparisons, including the direct checks, run per casting run; eligible pairs beyond that limit stay unmerged and are counted in a separate notice. Every comparison and its answer are checkpointed in the analysis record with the progress, and resume replays them without asking the model again. Pairs left separate by capacity failures or the limit, at most 256, are passed to casting as same-performance hints. Repeated batch descriptions and merged characters keep their distinct descriptions instead of replacing them; a description whose normalized words already appear in order inside the other, or that equals its beginning up to a partial last word, is not repeated, and a combination over 1000 characters keeps the earlier description. When a new description starts with at least 8 words of the stored description and then continues differently before the stored description ends, only its text after those shared words is added, so a reply that repeats the 300-character registry text of a longer description before a new detail adds only that detail.

Analysis records `gender` (female, male, unknown) and `age_band` (child, teen, adult, elderly, unknown) for each character. A known value must cite passage evidence from the current targets or context; only cited passages naming the character (any label, canonical form) or holding a part voiced by it count; the prompt forbids inferring either from a name alone or from grammatical agreement with a descriptor noun. Evidence IDs outside that window are dropped. A trait with an invalid value or without remaining evidence is read as unknown and adds no evidence; it never rejects the batch. Each trait keeps evidence separately for every known value, counted as unique passage IDs and capped at 100 per value, so the cap never removes every citation of a competing value. The value with the most retained unique passages wins; a tie at the top is unknown with a `conflict` flag. Voting counts only retained citations, so at saturation 101 female against 100 male citations is a 100/100 conflict. The value is recomputed after every batch and merge, so later evidence can resolve a conflict. Later batches and merges combine aliases, descriptions, evidence and traits; nothing is overwritten. Evidence capped at 50 passages: first supporting passage of every label, trait value and kind kept first, then earliest others. A trait saved in the earlier single-list form counts as evidence for its stored value; an earlier conflict has no attributable evidence and reads as unknown. Registry entries saved before these fields existed are read as unknown, and records without kind votes count their stored kind once. Casting schema 6 restarts incomplete analysis saved by an earlier schema, and an unfinished analysis whose stored passages no longer match the current segmentation is rebuilt from fresh passage placeholders, which is refused when any of its passages has audio. Complete analyses and frozen casting are not rewritten. Merged speaker assignments and the final frozen cast are published in one SQLite transaction. Casting uses a reusable narrator repertoire. It builds local conflict edges between speakers in the same paragraph or nearby dialogue paragraphs. Inside a run, two speakers conflict only when their paragraphs are <6 positions apart (window 6, locked by user 2026-10-05, no gold-set measurement); each run paragraph, narrator-only one included, = one position. Long scene no longer makes everyone conflict. A dialogue run stays open across one narrator-only paragraph in the same chapter and scene; a second consecutive narrator-only paragraph, a heading, other non-paragraph block, scene change or chapter boundary ends it. These are bounded structural contexts, not a semantic scene detector. Narration inside a dialogue paragraph does not split its context. Source order and speaker weights are checkpointed for every analysed chapter, including chapters not selected for audio. The analysis record also holds the stage progress shown by the interface: analysed target passages of all analysis passages, alias comparisons done of those planned, and voice assignment. The finished voice-assignment stage is kept only while the generation waits for cast review; Start narration removes it, and narration that starts automatically stores none. The interface shows a stage only while the generation analyses or casts, or is queued with unfinished analysis; a queued generation with complete analysis shows `Queued · ready/total`.

Pack profiles have roles. `narrator` and `narrator_variant` profiles are never cast to characters; `mechanical` profiles go only to characters of kind `mechanical`, which use character profiles, with a notice, when the pack has none; people and collective speakers use `character` profiles. A performance identity joins profiles that share a `family`, a case-insensitive CustomVoice speaker, or a checksum-identical clone neutral recording, and it includes the narrator. Metadata the active variant does not render, such as a speaker label on a clone profile, is ignored. A character with unknown or disputed gender whose pool declares genders first gets a gender target from the book's known-gender speech: largest speaker first, each joins the gender group that keeps the running balance closest to that ratio. A deterministic, most-constrained-first assignment orders characters by distinct neighbouring performances and conflict weight, then known gender before unknown, then speech volume. It ranks profiles of the character's pool by gender incompatibility, then weighted local performance collisions, then a missed same-performance hint for a possible alias that never shares a local context with the character, then sharing the narrator's performance, then gender fit or fit to the gender target, then age-band fit, then descriptive tag matches, then the speech volume already assigned to that performance, then profile ID. All fit terms are multiplied by the character's speech volume. Each fit has three levels: exact match, profile without that metadata, explicit mismatch; an unknown character trait is neutral apart from its gender target. A deterministic local search then tries single reassignments and pair swaps of speaking characters within their pools until a full pass changes nothing. It accepts a change when the cost of the moved characters, compared in the order incompatibility, collision weight, missed hints, narrator sharing, gender fit, age-band fit, tag matches, strictly drops. The same ordered cost over the whole cast strictly decreases with every accepted change, so the search ends. Changes are scored only for the characters they move, and casting stops when preparation is paused. Known-gender compatibility wins (user decision 2026-10-05): known gender gets compatible profile whenever pool has one, even if that performance is used nearby; collisions avoided among compatible profiles. Gender target for unknown gender stays soft. Only pool without compatible profile → another used, and the volume weighting moves such a mismatch to the character with less speech when a swap allows it. A profile without `gender` is compatible with every character but ranks below an exact match; an unknown or disputed character gender is compatible with every profile. When no compatible profile exists, the best remaining profile is used and the cast entry records `voice_compatible: false`. Cast entry records its gender target (`gender_target`, empty = none). A tag matches only as whole words, in order, inside one clause of the description, after NFKC normalization, case folding, removal of combining marks and ё→е. A tag preceded within two words by a negation (not, no, never, neither, nor, without, non, не, нет, без, ни; `n't` is read as not) does not match. Matching does not handle Russian inflection or translate between languages. There is no whole-book unique-voice requirement or unused-profile reservation. Reuse in separate contexts is normal and produces no notice; `voice_reused` marks a character whose performance another speaking character also uses. Each cast entry records the role, family and group of its profile and the character's kind. The assignments are frozen for each generation; this is neither an optimal graph-colouring claim nor proof of audible distinction.

Casting reports coded notices (`code`, `count`, `params`) and English warnings derived from them: `shared_performance_contexts`, `no_compatible_profile`, `displaced_for_collision`, `no_collision_gain`, `disputed_traits`, `pack_missing_metadata`, `alias_unmerged_capacity`, `alias_skipped_limit`, `unknown_gender_speakers`, `unknown_gender_unbalanced`, `unresolved_speech`, `degraded_passages`, `no_mechanical_voice`, `narrator_performance_shared` and `genderless_profile_for_gendered`. Preparation adds `delivery_not_supported` when a CustomVoice pack without instruction control receives expressive parts. Character notices name at most 20 characters. `unknown_gender_speakers`: unknown-gender speakers with gender target. `unknown_gender_unbalanced`: those without, because no known-gender character speaks. Cast saved before `gender_target` existed keeps first notice. `narrator_performance_shared` compares each speaking character with the narrator of every chapter in which it speaks: the narrator chosen for that chapter during review, else the chosen book default, else the cast narrator. A character that shares that narrator's performance identity in any of those chapters is counted once, and `params.chapters` lists the affected chapters. Parts of degraded passages count as degraded passages, not as unresolved speech. Conflicts and notices cover only the chapters selected for audio, although casting uses every analysed chapter. Cast review changes and corrections recompute them. The interface translates notices by code; generations saved before coded notices keep their English warnings, which the interface recognizes and translates. When the notices of such a generation are recomputed, the alias counts are read from its English warnings. In Russian, passage warnings and errors that join several messages are translated part by part; parts the interface does not know, such as raw worker output, stay as written.

After casting, preparation stops with status `review` while the `cast_review` setting is on, which is the default; the setting is read when the cast is committed. Nothing is synthesized until `start_narration`. During review a character can be renamed (the old name becomes the first alias), merged into another character (its lines move to the target and use the target's voice; the target keeps its name and kind, and the merged character's name becomes its first alias), given another kind (`cast_kind` with `person`, `mechanical` or `collective`), or given another profile from its pool, and the narrator or a narrator variant can be chosen for the whole book or for one selected chapter (`analysis.narrator_voices`). A kind change sets the character's kind votes so that they resolve to the chosen kind. When the current profile is outside the pool of the new kind, a profile of that pool is chosen again by gender incompatibility, then weighted local performance collisions, sharing the performance of the narrator of any chapter in which the character speaks (the narrator chosen for that chapter, else the chosen book default, else the cast narrator; for a character without speech, the book default or the cast narrator), gender fit or fit to the gender target, age-band fit and the speech volume already assigned to each performance; descriptive tags, alias hints and the local search are not used for this choice. Each change recomputes conflicts and notices. A passage correction saved during review creates a revision that also waits for review. Resume and audio repair return a generation in review unchanged, and Pause leaves it in review. With `cast_review` off, narration starts right after casting. The interface exposes the setting as `Stop for cast review before narration` and offers the changes in the Characters & narration panel. The panel lists speakers by share of speech with aliases, traits, profile family and notices, offers a kind select (Person, Mechanical, Group) and a voice select for each speaking character, and links to degraded and unresolved passages. Its list of passages without speaker analysis has one entry per degraded passage of the rendered chapters whose speaker is still `unknown`, so its count equals the `degraded_passages` notice.

Casting never rewrites source text. Unresolved speech, degraded passages and insufficient local differentiation are surfaced as limitations. A cast larger than the voice repertoire is not by itself a limitation. The baseline does not currently use Laya.

Presentation channel, content register and speaker identity are resolved separately.
EPUB import preserves bold/italic meaning declared by simple stylesheet classes and
retains common FB2 semantic classes (`cite`, `epigraph`, `poem`, `stanza`,
`text-author`, `subtitle`) as bounded analysis metadata. Styling is evidence rather
than a voice assignment: a bold phrase inside prose does not become a system card.
The context pass combines that metadata with structure, words and the existing
presentation channel to label a register such as prose, game system, telepathy,
written document, transmitted speech, item/stat card, location heading, quotation,
epigraph or poem.

A sealed narrator pack may carry a schema-1 `presentation_voices` profile learned
from that narrator's reviewed recordings. Channel and register rules either preserve
the assigned speaker, select a fixed performance, or map the assigned
voice/tag/prefix to a presentation-specific performance. Vlad Rimsky's reviewed
profile preserves radio, intercom and public-address speakers; it maps game readouts
and item/stat cards to mechanical stats, recordings to the mechanical envoy, and
telepathy or written/quoted documents to feminine or masculine mechanical families.
Registers without enough reviewed evidence stay visible for review. The same resolver
is used by corpus pre-labeling and production rendering; saved human decisions always
win. `scripts/scan_text_audio_realizations.py` is the generic per-book diagnostic for
finding printed-text/audio conventions before labeling begins.

## Audio execution

Only one generation is active at a time. Before analysis or synthesis starts, the worker checks that the speech model folder exists and that the selected device is available; otherwise preparation fails with `The selected device is not available for speech synthesis. Choose another device in Settings and resume.` Start and Resume adopt the device currently chosen in Settings. Text-model memory is released before speech synthesis. A successful render reply is validated and saved before honoring a concurrent Pause; invalid or unreturned speech is not accepted merely because a file exists. Each request renders a bounded passage into an atomic WAV file; its digest and metadata are saved before marking that segment ready. The configured model pack is checksummed again before use. The size, modification time, change time (`st_ctime`) and file ID (`st_ino`) of every sealed file are compared with the values seen at verification before the inference process starts, immediately before and after every request to the inference process (device check, analysis, alias comparison and synthesis), again after synthesis before its audio is published, and immediately before and after every alignment request; the set of files and symbolic links in the pack folder, ignoring operating-system metadata, is compared as well, so a file or link added during preparation also counts as a change, and so does a sealed path that now leads outside the pack. A difference stops preparation with `Model pack files changed after verification. Select the pack again in Settings.`, and cues returned while the files changed are not saved. On Windows `st_ctime` is the creation time, so a same-size rewrite that restores the modification time is not detected there. A reply received while the files changed is discarded: no analysis result or alias decision from it is saved, and its audio is deleted, not marked ready and not reused. If the pinned pack directory cannot be loaded, the currently selected pack and then a bundled pack are accepted only when they have the same pinned fingerprint; actual files are verified again before preparation. The saved configuration is not changed by this relocation. A pack that declares a text context below 8192 tokens cannot be selected or used for new analysis. Selection has one exception: a pack with 4096 to 8191 tokens whose fingerprint an existing generation is pinned to, for example after its folder moved, can be selected again so that those generations resume and repair, while the health check still reports `Text model context must be at least 8192 tokens.` and new generations stay blocked. A generation already pinned to a pack with 4096 to 8191 tokens still renders, resumes, repairs and accepts cast review and corrections, while starting or resuming its unfinished analysis is refused with the same message. After startup, a background thread checks the selected pack folder; the startup handshake does not wait for it. When the folder no longer contains `pack.json`, Settings switch to the bundled pack whose fingerprint matches the newest pin among the generations made from that folder. Each new generation records when its pack was pinned (`config.pinned_at`), and a corrected version keeps the pin time of the generation it corrects, even after that generation is deleted. When no generation made from that folder has a pin time, as for generations made before this version, this rule switches only when all of them share one fingerprint. Otherwise, when the stored path has the shape of a bundled pack location (`…/<resource folder>/packs/<name>`), Settings switch to the bundled pack with the same folder name, or else to the sole bundled pack. Any other missing custom folder stays selected, and the health check reports it. A selection saved while this check runs is kept.

The audio reuse key (schema 3) includes the exact spoken text, pinned pack, device setting, synthesis voice (the exact CustomVoice speaker, or the checksum and transcript of the clone reference actually used), the delivery actually applied (neutral when the pack has no delivery control or the clone profile lacks that reference), the speech language, the speech adapter version and the take number. The speech language follows the book's declared language and the script of its first narratable text, and is `Auto` for other languages. It is pinned in the generation (`analysis.speech_language`) when the generation first reaches rendering, and rendering and alignment reuse it after every resume, repair and revision, so later changes to the book metadata or to the detection rule do not change it. A generation from an earlier version without a pinned value pins the earlier rule (`Russian` for a declared language that starts with `ru`, `English` for `en`, otherwise `Auto`) in two cases: when any of its passages has a stored audio key, including passages that an audio repair reset, and when its analysis was completed by a version without the cast review step and accepted audio exists under the earlier schema-2 key of any of its passages. Otherwise it pins the current rule. Segments that already have audio keep their stored key. When no accepted audio exists under the current key, an audible passage at take 0 reuses accepted audio saved under the earlier schema-2 key (pack, device, spoken text, voice ID, requested delivery and the earlier language rule) only when the generation's pinned language equals that earlier rule, or when the pack's `speech.language_mode` is `auto`, because the worker then always conditions with `Auto`; a damaged earlier file is synthesized again. A generation therefore does not mix audio conditioned with different languages. Passages without letters or digits share one 0.3-second 24 kHz silence file and are not synthesized. Completed matching audio is reused across revisions. Changing a pronunciation or speaker creates a new saved generation; the original is retained. A New take correction renders an unchanged passage again under the next take number for that passage in the book. When missing or corrupt audio is regenerated under an existing key, an on-disk repair marker precedes metadata publication. All database references receive the measured replacement duration and lose stale word cues in one transaction; only then is the marker cleared. Interrupted publication can replay this repair from valid saved audio without another synthesis. Playback and export refuse an uncleared marker. This does not overwrite healthy audio or invalidate its cues.

Runtime replies require an exact request identity and an unambiguous result/error envelope. Cancellation is checked before dispatch and while sending the request. A bounded sender thread prevents an unresponsive child stdin from bypassing the deadline or Pause; requests are limited to 4 MiB of UTF-8 JSON. The operation deadline covers both request transmission and the response wait. Worker cleanup cannot leave the active slot permanently occupied. Errors for an exited worker end with the last 3,000 bytes of its error output. Worker error replies carry the plain message of application errors and `Type: message` for other exceptions.

Closing the desktop window hides it to the system tray; the local runtime and an active preparation remain alive. The tray opens the window again and provides the explicit Quit action. Quit closes the runtime and releases its inference resources; no operating-system service or detached renderer remains active after the application process exits. A generation records durable restart intent only while it is active. A graceful Quit or crash preserves that intent and the next application launch automatically resumes the newest interrupted generation from committed analysis and accepted audio. Explicit Pause clears the intent before signalling the worker, so Pause still wins when Quit follows immediately. Terminal ready, held, review and failed states also clear it.

Shutdown permanently closes the job scheduler under the same lock used to start a generation, so an already waiting request cannot reopen it or clear its stop signal. A failed or paused job can resume from accepted audio and committed analysis batches. A queue-write or thread-start failure releases the active slot. A failed synthesis request is retried once with a fresh worker. When the retry also fails because the worker reported an error, the passage is marked `failed` with the worker message as its warning (a message over 2,000 characters keeps its first 500 and last 1,497 characters around ` … `), the generation fails with `A passage could not be synthesized after a retry. Open the marked passage to correct its spoken text, then resume.`, and Resume renders that passage again. Retry fails because worker exited, timed out or broke protocol → no passage marked; generation fails with `The speech worker stopped twice while rendering a passage. Resume to try again.` + worker message. Speech shorter than 0.02 s per letter or digit minus 1 s, or longer than 0.8 s per letter or digit plus 20 s, is rendered once more; if that attempt fails, the first take is restored, worker that exited/timed out/broke protocol replaced before next passage, and a take that is still outside the bounds is kept with `Speech duration looks unusual for this passage. Use New take if it sounds wrong.` Unreferenced audio is collected after every job and after explicit deletion, and is skipped while a generation is active. Startup removes only interrupted imports (`books/.import-*`), folders of interrupted book deletions (`books/.deleted-*`), export staging (the contents of `work/`) and unpublished temporary audio (`audio/.pending-*`); it never deletes book folders or audio because the opened database does not reference them. A generation is ready only when all expected selected-chapter segments are ready. Analysis is not considered complete because a model returned syntactically valid text; the source-coverage checks must pass.

The current scheduler renders explicitly requested chapters. The progressive pass
policy above is the target for the rolling ahead buffer; the present scheduler does
not yet reprioritize generation after an arbitrary playback seek. Playback can wait
for a pending segment while its existing job continues.

## Playback, subtitles, and pictures

The webview audio element plays authenticated WAV blobs from the local service. Asset retrieval validates their samples, checksum and completed repair state rather than trusting a ready database row alone. Playback tracks explicit Play intent separately from audio loading so late promise errors cannot cancel a newer action. Polling never restarts an already loaded externally paused element; a newly completed pending passage can still continue requested playback. It stores generation/source/segment position independently of a mutable whole-book timestamp. During continuous playback the next ready passage is fetched and decoded in a second audio element and takes over when the current one ends; the remaining gap has not been measured. A character preview plays one passage without saving listening or reading positions and then restores the previous passage. Caption timing follows actual `currentTime` and therefore playback speed and seeking, not a wall-clock timer.

Passage subtitles require no aligner. The optional isolated Qwen aligner adds word cues and reuses one loaded process per generation. Cue timestamps and coverage of the spoken text are validated. Invalid alignment is not published as precise timing; passage captions are retained. When the aligner exits, times out or cannot start, alignment stops, the remaining passages get `Word alignment stopped because the local aligner exited; passage subtitles are kept.`, and the generation is still published when its audio is complete. Passages whose alignment failed are recorded, and Check and repair counts neither them nor passages without letters or digits as missing alignment. The rich reader highlights source passages; it does not claim word-level highlighting inside original MathML or pronunciation-overridden source text.

Pictures attach to paragraph IDs. The latest saved version appears after that paragraph in Reading view; Illustrated view selects the exact current paragraph and provides source-anchor navigation. Original figures remain at their source locations. Images are shared across narration versions and do not change EPUB bytes or spoken text. The optional serial Codex queue has explicit selection, consent, bounded output validation, saved progress and retry/local-finalization controls. It requires an existing installed CLI, found on PATH or in common user and package-manager install folders; the health check reports whether it was found. Live image execution remains unverified. A separately consented Image API action does not act as a hidden fallback; its HTTPS requests trust the system certificates plus the `certifi` certificate bundle. See [PARAGRAPH-ILLUSTRATIONS.md](PARAGRAPH-ILLUSTRATIONS.md).

Playback-clock updates are isolated from chapter rendering. Memoized source/progress/visual indexes avoid repeated full-book scans. Display previews load near the viewport with a bounded idle Blob cache, while changed-generation polling still sends all segments/cues. Full-book text remains in memory and a complete chapter is mounted; this is not whole-book virtualization or measured hardware performance.

Study mode preserves and displays source equations, figures, and tables. It is not a physics tutor and does not validate generated scientific content.

## Export and storage

Export validates exact source-range coverage for the chosen chapters and decodes/checksums all accepted segment files before publication. All formats are staged privately and atomically published only after successful completion. Export selects complete chapters and assembles only saved audio. M4B chapter metadata uses measured sample durations. Caption files use recorded segment timing; when word cues exist, they are grouped into lines of at most 42 characters and 7 seconds that keep the spoken text's punctuation. A break after an initial or a common abbreviation (А. П., т. д., Mr.) ranks below every other break, and a sentence end counts only when the next word does not start in lowercase. A line shorter than 1 second is merged into a neighbouring line of the same passage when the result still fits those limits; otherwise the two lines are split again at a break where both fit and last at least 1 second, never after an initial or abbreviation, and stay as they are when no such break exists. Speech generation is never part of export. FFprobe must inspect each encoded audio output before publication. Codec, mono 24 kHz format, measured duration and (for M4B) chapter count, labels and timeline must match the frozen manifest. Duration tolerances allow 5 ms of rounding and up to 150 ms of encoding padding. The FFmpeg time limit grows with the audio length, from 30 minutes to 6 hours. These checks do not prove spoken-word fidelity or replace a listening evaluation. Subtitle-only export does not require FFprobe.

Export encodes outside the global mutation lock, so other library operations continue meanwhile; a separate lock allows one export at a time, and publication checks that the generation still exists. Cancel export stops hashing or encoding and publishes nothing: `Export cancelled. No incomplete output was published.` The interface offers Cancel only while the runtime export runs, not during the save dialog or the refresh that follow it. Application shutdown cancels managed FFmpeg execution and waits for mutating requests before closing the database. Native external export copying uses a sibling staging file; target-platform acceptance remains outstanding.

SQLite holds relationships/state and files hold large assets. Files exported outside the library are independent of internal cleanup. Audio deletion respects references from other generations. Book deletion commits all dependent records together; file cleanup follows commit rather than preceding it. The book folder is first renamed to `books/.deleted-<random id>` and then removed. A failed removal is reported; a renamed folder is removed at the next start, while a folder whose rename failed stays in place. Failed standalone database writes roll back their effects. No time-based audio expiry is enabled. On macOS and Linux the library lives in the application data directory. On Windows it lives in its own `library` folder under `%LOCALAPPDATA%\app.rimskifikator.desktop`, apart from the WebView2 profile; a library in the earlier roaming `%APPDATA%\app.rimskifikator.desktop` folder is moved there by one folder rename and stays in `%APPDATA%` when that rename is not possible.

The current library uses SQLite user_version 4. Its transactional upgrades preserve source, existing audio and pinned settings while adding independent reading positions and bounded per-item revision journals. Generation status `review` and passage status `failed` are stored in existing columns and need no schema change. Opening a newer schema is refused before any schema/version mutation.
